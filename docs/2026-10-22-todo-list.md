## To-Do List (CLI)

Arquivo: `todo-list/todo_list.py`

### O que o código faz

| Função | O que faz |
|---|---|
| `load_tasks()` | Carrega a lista de tarefas do `tasks.json`. Retorna lista vazia se o arquivo não existir ou estiver corrompido. |
| `save_tasks(tasks)` | Salva a lista inteira no `tasks.json`, formatada (`indent=2`) e legível. |
| `ask_text(prompt)` | Lê um texto do usuário, repetindo a pergunta se vier em branco. |
| `ask_date(prompt)` | Pergunta uma data no formato `AAAA-MM-DD`; Enter em branco retorna `None` (tarefa sem prazo). |
| `ask_task_number(tasks, prompt)` | Pede o número de uma tarefa (1-based) e retorna o índice (0-based) correspondente, validando o intervalo. |
| `is_overdue(task)` | Retorna `True` só se a tarefa tem prazo, não está concluída e o prazo já passou (`datetime.date.today()`). |
| `format_task(index, task)` | Formata a linha de exibição de uma tarefa, colorida de acordo com o status (concluída/atrasada/normal). |
| `add_task(tasks)` | Pergunta a descrição e o prazo (opcional) e adiciona a tarefa. |
| `list_tasks(tasks)` | Imprime todas as tarefas, na ordem em que foram adicionadas. |
| `toggle_task(tasks)` | Alterna o status concluída/pendente de uma tarefa escolhida pelo número. |
| `delete_task(tasks)` | Remove uma tarefa escolhida pelo número, com confirmação. |
| `show_menu()` | Imprime o menu principal (`MENU`). |
| `main()` | Carrega as tarefas uma vez no início, mostra o menu em loop e despacha pra cada função, salvando no JSON depois de qualquer operação que mude os dados. |

Constantes de suporte: `RESET/GREEN/RED/YELLOW/CYAN/BOLD` (cores ANSI, mesmo padrão dos projetos anteriores), `TASKS_FILE` (caminho do JSON montado a partir da pasta do próprio script) e `MENU` (dicionário opção → rótulo).

### Por que foi feito assim

- **Tarefas são selecionadas por número de posição na lista (1-based), não por nome.** Diferente do Contact Book (onde o nome é um identificador natural e praticamente único), tarefas podem ter descrições repetidas ("Comprar pão" duas vezes é normal) — usar a posição evita ambiguidade sem precisar inventar um ID artificial. `toggle_task`/`delete_task` sempre mostram a lista antes de perguntar o número, pra garantir que o usuário está vendo os números atualizados.
- **`is_overdue` trata uma tarefa concluída como nunca atrasada, mesmo que o prazo já tenha passado.** Atraso é um aviso sobre algo que *ainda precisa ser feito*; uma tarefa já concluída não precisa desse alerta, independente de quando ela foi terminada.
- **`prazo` é opcional (`None`) em vez de obrigatório.** Forçar uma data pra toda tarefa empurraria o usuário a inventar prazos falsos só pra poder cadastrar algo sem data definida — `ask_date` aceita Enter em branco exatamente pra não criar essa fricção.
- **Datas armazenadas como string ISO (`"2026-10-27"`) no JSON, convertidas pra `datetime.date` só na hora de comparar (`is_overdue`).** JSON não tem um tipo nativo de data; guardar como string ISO (em vez de, por exemplo, timestamp numérico) mantém o arquivo legível por um humano que abra o `tasks.json` direto, e o formato ISO ordena alfabeticamente igual cronologicamente.
- **`todo-list/tasks.json` foi adicionado ao `.gitignore`**, pelo mesmo motivo do `contacts.json` do Contact Book: é dado gerado pelo programa em tempo de execução, não código-fonte.
